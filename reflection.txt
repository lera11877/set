Навіщо Git у сучасних проєктах?
Git є невід'ємним інструментом у сучасній розробці, оскільки він забезпечує контроль версій, 
дозволяючи точно відстежувати кожну зміну в коді та повертатися до будь-якого попереднього стану проєкту. 
У командній роботі Git та GitHub є центральною платформою для співпраці, ізоляції функцій за допомогою гілок
 та безпечного об'єднання коду.

Особистий досвід після виконання завдання
Можу відзначити, що робота з командним рядком та Git була для мене складною, оскільки раніше я з
 цим не працювала, і виникало багато непередбачуваних помилок. Проте, отриманий досвід виявився 
 надзвичайно цінним і показав важливість послідовності та точності команд.


Що виявилось найзручнішим/найважчим
Найзручнішим у роботі з Git виявилася можливість робити змістовні коміти, що дозволяє швидко фіксувати
 зміни та бачити історію своєї роботи. Найважчим моментом, який вимагав найбільше уваги та зусиль, 
 було об'єднання гілок (Pull Request / Merge) та коректне використання команд для перейменування (reword) старіших комітів.

 
Як це застосувати у курсовому або колективному проєкті
У майбутньому курсовому або колективному проєкті я планую застосовувати концепцію гілок для ізоляції
 роботи над окремими модулями або функціями. Це гарантує, що основна робоча версія коду (гілка main)
  завжди залишатиметься стабільною, а зміни будуть вноситися лише після успішної перевірки.
